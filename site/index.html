Weir is an OpenAI-compatible gateway for teams that share LLM spend. Every team gets its own key, rate limits and a token budget that holds even when a thousand requests land at once. Streams pass through untouched.

    One request, five steps

    Each request costs the gateway two Redis round trips, both single Lua scripts, so any number of gateway instances agree on every limit without locks.

    1. Authenticate

      The team's key is hashed and looked up. Your provider key never leaves the gateway.

    2. Reserve

      Prompt tokens plus max_tokens are reserved against the budget, in the same atomic step as the per-minute limits.

    3. Fit

      Not enough budget left for the full answer? max_tokens is lowered to what remains, so the provider can't overspend.

    4. Stream

      Provider bytes go straight to the client as they arrive. Usage is read off the final event without holding the stream.

    5. Settle

      The reservation is released and real usage is charged. This still happens when a client hangs up mid-answer.

    When something breaks

    An outage in the limiter shouldn't take every AI feature down with it. Weir degrades in a defined way for each failure.

    Redis is slow or down
    A circuit breaker opens after a few failed calls, so requests stop waiting on it. Known teams keep being served under a per-process rate limit, marked x-weir-degraded. Set FAIL_OPEN=false to refuse instead.
    Unknown key during an outage
    Refused with 503. Staying open never means serving unauthenticated traffic.
    Provider returns an error
    The status and body pass through unchanged. The reservation is released and nothing is charged.
    Provider is unreachable
    OpenAI-style 502 or 504. After repeated failures a second breaker answers 503 immediately.
    Client hangs up mid-stream
    The upstream connection is closed, which stops generation. Tokens already produced are charged.

    Measured on a 2-core machine

    Every figure comes from the load scripts in the repository, run with the gateway, Redis, the mock provider and the load generator sharing two vCPUs.

    The throughput gap comes from httpx's default connection pool, which does work proportional to the number of open connections on every request. Weir ships its own HTTP/1.1 transport for httpx that pools in constant time and reads directly from asyncio streams.
